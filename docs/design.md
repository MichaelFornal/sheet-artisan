# Sheet Artisan: system design

## Context

Mike wants to stand out to employers and founders by handing them a **niche, unique, valuable dataset** as an Excel workbook, together with concrete suggestions for how the business could use it. It is emailed or attached as part of an application package, and the pipe that built it is shared on GitHub. It has to be **repeatable**: one Claude session per company takes a run from company research to finished sheet and repo.

This session decides only *what the system is*. After approval we build it, and then Mike test-drives it on a real company. **Nothing from jb is reused.** It is a new, standalone project.

### Decisions locked this session
| Topic | Decision |
|---|---|
| Run input | A company Mike names, plus an optional job-posting URL |
| Time | About 3–3.5 h of hands-on session work. Crawls may run unattended for many hours on top, so pipes must be resumable |
| Mike's role | **Live in every brainstorm** (5 of them) plus one 5-minute sample check |
| AI step | Only when it earns its place: considered at every ideation, used where a regex can't do the job. Runs on `claude -p` ($0), with a cache/offline mode |
| Form factor | Project folder + `CLAUDE.md` runbook. No slash-command skill |
| Suggestions | Live in the workbook ("Start Here" tab plus one tab per use). The email stays short |
| GitHub | Pipe + ~25 sample rows by default. **Per-source `private` flag** withholds methods that shouldn't be public. **Three sharing tiers**: public / private-invite / none |
| Private tier | Private repo on Mike's own account; the recipient is invited by email. (Verified in GitHub docs: invite-by-email works, but the invitee needs a GitHub account, and personal-repo guests always get **write** access. Accepted.) |
| Recipient email | Self-published address first. Otherwise infer the company's pattern (first.last@…) from real named addresses at that domain found on the public web, with evidence URLs recorded and the address labelled "pattern-derived" |

## A run at a glance

```
SITTING 1 (~2h)                                   UNATTENDED           SITTING 2 (~1–1.5h)
Kickoff → B1 Company → B2 Ideation → B3 Sources   make full crawl      QA → B4 Insights → Package → B5 Ship → Retro
          (live)       (live)        (live)       (mins to many hours,        (live)                (live)
        → Build → Sample check (live, 5 min)       resumable, logged)
```
Two sittings, because the crawl sits between them. One Claude session can span both by waiting on the background crawl. If the session dies, `runs/<slug>/run.md` holds enough state for a fresh session to resume at the right stage.

**WebSearch budget** (~200 per session, shared by all agents): B1 ≤30 · B2 ≤30 (existence checks) · B3 ≤60 (source discovery) · reserve 40 for build and recipient lookup. Beyond that, use WebFetch on known URLs. `run.md` tracks the count.

## The five brainstorms (the repeatable core)

Every brainstorm follows one shape. **Claude prepares** (research done before talking), **presents** a compact artifact, **asks Mike 2–4 pointed questions**, then **records the decision** in `run.md` and writes the stage artifact. Each is time-boxed.

### B1 · Company read-back (20 min, ≤30 searches) → `01_brief.md`
- **Prepare:** the company's site (product, pricing, customers and case studies, careers), the posting if given, stage and funding, 3–5 competitors, recent news and launches, and its public-data footprint (API, open data, what it blogs about).
- **Present:** a one-page brief covering what they sell · who buys · how they make money · stage/size/geo · what's changing · the role and which skills it wants to see. Plus the **decision map**: 6–8 recurring decisions their people make × who makes each × what information they'd want × what they likely use today. Plus a **recipient hypothesis**: who reads this and what they care about.
- **Ask Mike:** What's wrong or missing? Which 2–3 decisions do we aim at? Who's the recipient? Any angle you already have?
- **Record:** the aimed decisions, the recipient, the angle.

### B2 · Dataset ideation (25 min, ≤30 searches) → `02_ideas.md`
- **Prepare:** 12–15 **idea cards**, generated by walking a *fixed lens list* against the aimed decisions. The fixed list stops every run from converging on "a competitor list". Lenses:
  1. Prospects / customers with trigger signals
  2. Competitors & market map
  3. Partners / channel / supply
  4. Public records & regulation (permits, licenses, inspections, filings, grants, contracts, recalls, patents)
  5. Demand & sentiment (reviews, forums, job posts, app stores)
  6. Prices & catalogs
  7. Geography & coverage gaps
  8. Change over time (snapshots → deltas)
  9. Their own public footprint
  10. The wildcard join: two public sources nobody has joined
- **Card fields:**
  - title
  - grain ("one row = …")
  - 6–8 columns
  - the decision it serves
  - candidate sources
  - **existence check** (can they already buy or download this? where, at what price?)
  - estimated rows and crawl time
  - feasibility risk
  - the **10-second wow**
  - the skill it showcases
  - AI step? (y/n and why)
  - **sensitivity** (none / personal / outreach / sensitive), which determines the allowed tiers
- **Score 1–5:** Value ×3 · Uniqueness ×2 · Feasibility ×2 · Wow ×2 · Showcase ×1. **Legitimacy is a gate, not a score.**
- **Present:** a ranked table of the cards, with a one-liner for each of the rest.
- **Ask Mike:** Pick 2–3 to spike. Kill, merge or modify any? Add your own?

### B3 · Source spike & spec freeze (35 min, ≤60 searches) → `03_spec.md`, `sources.yaml`
- **Prepare:** for each shortlisted card, find concrete sources and **probe each live with one real request**. Record for each:
  - endpoint or URL, and method (API / bulk file / sitemap+HTML / PDF)
  - auth, robots.txt verdict, ToS note
  - pagination and rate limit
  - **a pasted real sample record** (the fields that actually exist)
  - coverage estimate (API total, sitemap size)
  - full-crawl time (requests × delay)
  - publish flag (public/private method)
  - whether an AI step is needed

  Anything blocked is killed here.
- **Present:** a feasibility table with a verdict per candidate, plus the draft spec for the leader.
- **Ask Mike:** Which is the final dataset? Confirm the grain, columns, scope filters (geo / size / date window), target size, and provisional sharing tier.
- **Freeze `spec.md`:**
  - grain
  - columns (name, type, definition, source, derived?)
  - key + dedupe rule
  - joins
  - filters
  - AI step (prompt + output schema)
  - crawl plan (sample N → full)
  - sensitivity + tier

### B4 · Insights & business uses (20 min, 0 searches) → `04_insights.md`
- **Prepare:** profile the full data.
  - 8–10 candidate **findings** (concentrations, top-N, gaps, outliers, surprising absences, deltas). Each is computed by a named function in `facts.py` and lands in `facts.json`.
  - 6–8 candidate **uses** tied to the aimed decisions. Each has: the use · who on their team · the exact filter and sort (this becomes its own tab) · what they'd do Monday morning · example rows.
- **Ask Mike:** Which finding is the headline that opens the email? Which 3–5 uses? Does anything read as an overclaim?

### B5 · Ship review (15 min) → go / no-go
- **Present:**
  - the workbook, opened
  - `email.md`
  - the recipient, route and evidence
  - the staged repo for the chosen tier (file list + what was stripped)
  - gate results (claims check, scan)
- **Ask Mike:** What edits? Which final tier? Go or no-go to publish?
- **Then:** `publish.py` creates the repo (and Mike sends the invite for the private tier). **Mike sends the email himself.**

### Non-brainstorm stages
- **Kickoff (5 min):** `tools/new_run.py "<Company>" [--posting URL]` → creates `runs/<slug>/` and scaffolds the pipe repo.
- **Build (~60 min, autonomous):**
  - one module per source
  - normalize → join/dedupe → derive (AI step) → workbook
  - `make sample` first, and build the workbook from the sample so packaging code exists before the crawl
- **Sample check (5 min, Mike):** 25 rows in the sample workbook. "Is this what we meant?" Spec changes are cheap now and expensive after a 6-hour crawl.
- **Crawl (unattended):** `make full` in the background under `caffeinate -i` (keep the Mac plugged in). It resumes from the raw cache, and a progress log is written to `run.md`.
- **QA (10 min, autonomous):**
  - row count vs estimate
  - null rate per column
  - duplicate keys
  - value ranges
  - **20 random rows re-fetched live and compared**

  Hard failures block B4.
- **Package (20 min, autonomous):** workbook, email draft, README, recipient lookup.
- **Retro (5 min):**
  - append every source found (with access notes) to `catalog/sources.md`
  - append unpicked ideas to `catalog/ideas.md`
  - append traps to `catalog/learnings.md`
  - add a row to `catalog/outcomes.md` (sent date, tier, reply) so the system learns what actually gets responses

## Deliverables

**Workbook** `out/<Company>_<Dataset>_<YYYY-MM-DD>.xlsx` (≤10 MB for email; if larger, attach the top-N and link the rest):
1. **Start Here**: what this is (1 sentence), the headline finding, 3–5 uses (each one line, linked to its tab), how it was built + repo link, freshness date, contact.
2. **Data**: the main Excel Table (filters, frozen header). Every row carries `source_url` (hyperlinked) and `fetched_at`.
3. **Use tabs**: one pre-filtered, sorted view per chosen use.
4. **Summary**: computed tables + 1–2 native charts.
5. **Dictionary**: every column, with definition, type, source, derived?
6. **Sources & Method**: per source: URL, access method ("withheld" for private methods in the public tier), date, rows, license/ToS note.
7. **QA & Limits**: checks run, results, coverage gaps.

**Email** `email.md`: 4–6 sentences. A hook built on the headline finding · what's attached · "open Start Here" · the repo link or invite note · the ask. Plus a specific subject line. Delivery routes: email the recipient (primary) · attach in the ATS's "additional documents" field · link from the cover letter.

**Repo**: README (what, why it's hard, how to run `make sample`/`make full`, a sample of the output), the pipe, the vendored kit, ~25 sample rows. The public tier **never names the target company**; the dataset is their gift until they respond. Repos are named after the niche.

## Sharing tiers & the publish gate
| Tier | Where | Contents | Allowed when sensitivity is |
|---|---|---|---|
| `public` | `MichaelFornal/<niche-slug>` public | Pipe minus `private` sources (code removed, Sources tab says "withheld"), 25 sample rows | none |
| `private` | `MichaelFornal/<slug>` private + email invite (guest gets write) | Full pipe | any |
| `none` | no GitHub; optional scanned `.zip` in the package | — | any |

`tools/publish.py --tier X` does the following, in order:
1. Stages a copy into a temp dir.
2. Enforces the tier/sensitivity table.
3. Strips private sources.
4. Scans for secrets, `/Users/` paths, emails/phones and the target's name (public tier).
5. Prints exactly what will be created.
6. Runs `gh repo create` **only after Mike's explicit go**.

The private-tier invite is sent by Mike in the GitHub UI; the script prints the settings URL.

## Standing rules (the floor)
- **Access:** public data only. Never bypass logins, paywalls, CAPTCHAs or blocks. The fetcher honors robots.txt, uses ≤1 req/s/host by default, honors Retry-After, uses **decaying** 429 backoff, and sends an identifying User-Agent.
- **Honesty:**
  - Every row carries a source URL. Nothing invented.
  - LLM-derived columns are labelled, and their prompts are cached.
  - **Every number in Start Here / the email / the README is a `{{fact:key}}` rendered from `facts.json`.** `claims_check.py` fails on any other digit (dates allowlisted).
- **Personal data:** only what people published professionally. Sensitivity decides the tier.
- **Email pattern:** derived only from ≥1 real address at that domain found on the public web (URL recorded). Labelled "pattern-derived". No SMTP probing. A self-published address always wins.
- **Outward actions:** creating a repo, sending an invite or sending the email always require Mike's go.
- **$0:** free sources plus `claude -p`.

## What we build (implementation, after approval)

```
~/Documents/sheet-artisan/            own private git repo, local only (no remote)
  CLAUDE.md                           runbook: stage order, rules, start/resume a run, search budget
  docs/design.md                      this design, copied in as the system's spec
  playbook/                           one guide per stage: kickoff, b1-company, b2-ideation (lenses, card, rubric),
                                      b3-sources (probe checklist, spec freeze), build, sample-check, crawl, qa,
                                      b4-insights, package (workbook tabs, email), b5-ship (tiers), retro
  templates/                          brief.md, idea-card.md, spec.md, sources.yaml, start-here.md, email.md, README.md, run.md
  kit/                                vendored into every pipe so each published repo runs standalone
    fetch.py                          disk cache (URL+body hash), robots, per-host throttle, Retry-After, decaying backoff, resumable
    llm.py                            claude -p → JSON-schema output, cached by prompt hash, --offline replay
    workbook.py                       writes the 7-tab workbook from spec + tables (openpyxl)
    qa.py                             standard checks + live spot-check sampler
    facts.py                          fact registry → facts.json; renders {{fact:key}} templates
  tools/
    new_run.py                        scaffolds runs/<slug>/ + pipe repo (Makefile: sample, full, sheet, qa, facts)
    publish.py                        tier gate → stage → strip → scan → (Mike's go) → gh repo create
    scan.py, claims_check.py
  catalog/                            sources.md, ideas.md, learnings.md, outcomes.md (grow every run)
  tests/                              kit + tools tests, and a toy end-to-end run on a local fixture server
  runs/<slug>/                        gitignored: run.md, 01–04 stage docs, spec.md, sources.yaml, pipe/ (own git repo), out/
```

**Build order:**
1. Folder + `git init` + `CLAUDE.md` + `docs/design.md`.
2. Playbook guides + templates.
3. Kit, test-first (fetch against a local HTTP server: cache hit, robots refusal, 429 → Retry-After → decay; workbook: all 7 tabs, table, hyperlinks; facts render; qa checks).
4. `new_run.py`, `publish.py` (with `--dry-run`), `scan.py`, `claims_check.py`.
5. A toy end-to-end run.
6. Save a memory entry for Sheet Artisan.

Dependencies stay light (`requests`, `openpyxl`, `pyyaml`). Check the Python version and what's already installed before choosing a venv.

## Verification
1. `make test` in `sheet-artisan/`: all kit and tool tests pass.
2. Toy run: `new_run.py "Toy Co"` → `make sample` against the fixture server → the workbook opens (`open out/*.xlsx`) with 7 tabs, working hyperlinks, and use tabs.
3. Gates prove themselves by failing:
   - a stray number added to `email.md` → `claims_check` fails, and passes once removed
   - sensitivity `personal` + `--tier public` → refused
   - a `private` source → absent from the public staging dir
   - the target's name in the README → the public scan fails
4. `publish.py --dry-run` for each tier prints the plan and creates nothing on GitHub.
5. **Mike's real test:** a fresh session in `~/Documents/sheet-artisan` → "new run: <company> [posting]" → the full 5-brainstorm flow → Retro captures what to tune in the playbook.

## Implementation notes (built 2026-09-19)
What changed from the plan above while building it, and why:
- **`sources.yaml` → `pipe/spec.json`.** System Python is 3.9.6 with no pyyaml. One JSON file is
  the whole dataset contract (grain, columns, key, sensitivity, tier, sources with publish flags)
  and every gate reads it. `03_spec.md` keeps the reasoning.
- **The kit is standard library + openpyxl.** `fetch.py` uses urllib, not requests, so a published
  pipe needs one `pip install`. Tests use `unittest` (no pytest).
- **One command line:** `./sa` wraps
  `tools/{new_run,stage,check_run,publish,scan,claims_check}.py`. `sa stage/search/decide` keep
  `run.json` + `run.md` current, which is how a fresh session resumes.
- **The repo URL is known before publishing:** `github.com/<owner>/<niche_slug>`. The workbook and
  email carry the final link, and `sa check` verifies it matches the tier.
- **Private collection methods stay withheld in the emailed workbook too,** unless
  `package.json` sets `show_private_methods: true`.
- **Deny terms** for the public scan are the company name as written, the name without its legal
  suffix, and the domain (`run.json`, editable when the name is a common word).
- **Verified:**
  - 66 tests, including a toy run end to end (scaffold → sample → full → spot → sheet → check →
    publish plans for all three tiers, against a local server);
  - one real `claude -p` batched call with an offline replay.
